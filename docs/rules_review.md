# 공식 안내 및 베이스라인 대조

확인 기준: 2026-11-14 KST. 규정 검토와 코드 수준 점검이며, 운영진의 최종 적합 판정을 대체하지 않습니다.

## 후속 OT 안내 반영

사용자가 제공한 OT 15~18쪽의 텍스트는 같은 실험의 현재·과거 센서·이미지와 초 단위 시간 윈도우를 허용하며, 과거 구간 평균도 사용할 수 있다고 명시합니다. 따라서 현재 행만 사용했던 초기 구현은 규정상 의무가 아닙니다. 후속 센서 실험에는 같은 실험의 과거 유효값 대체와 전압·전류·압력의 30초 평균·변화량을 추가했습니다. 구체적 정의는 [시계열 센서 실험 안내](temporal_sensor_experiments.md)를 따릅니다.

반복·행 순서·실험 분리·미래 제거·임의 부분 입력 검사는 기본적으로 모두 엄격하게 유지합니다. 필요한 과거 행을 제거하는 임의 부분 입력은 과거 기반 모델의 피처를 바꿀 수 있습니다. 연구용 `--diagnose_history_subset`을 명시했을 때만 이 차이를 별도 진단으로 표시합니다. OT에는 이 경우의 상세 검사 범위가 명시되지 않았으므로 공식 적합성을 자동 판정하지 않으며, 최종 제출 검사는 기본 엄격 모드로 실행합니다.

OT는 빈 이미지로 바꿨을 때 실제 예측이 바뀌는지를 최소 요건으로 확인한다고 설명합니다. CNN이 연결돼 있다는 사실만으로 충족을 보장하지 않으며, 최종 결합 담당은 실제 가중치로 이미지 기여도도 확인해야 합니다. 센서 단독 모델은 비교 실험용입니다.

## 코드에 반영한 사항

| 항목 | 반영 방식 |
| --- | --- |
| 현재 시점의 단계 1..6 분류 | 6개 logits, 제출 시 1..6 변환 |
| 이미지와 센서 모두 사용 | 이미지 CNN + 센서 MLP 결합 |
| Macro F1 | 6개 클래스를 고정해 평균, 클래스별 F1·support·혼동행렬 저장 |
| 이미지 경로 | `image_path`는 split 기준 상대경로. Train·Validation 기준 폴더 분리 |
| 이미지 형식 | 공식 RGB 의사색 설명에 맞춰 RGB 로딩·고정 resize. 온도 변환 주장 없음 |
| 누수 방지 | Train에서만 전처리·모델 학습, Validation으로 epoch 선택, Test는 추론 전용 |
| 실험 분할 | Train/Validation sample ID와 experiment ID 중복 거부 |
| 부분 입력 재현 | 기본은 현재 행 사용. 과거 옵션은 같은 실험의 현재·이전 행만 사용하며 입력 외 캐시 없음. 과거 제거 영향은 별도 진단 |
| 제출 진입점 | `test.py --input ... --image_root ... --output ...`, 추가 인자는 기본값 |
| 제출 파일 | ID·입력 순서 보존, 정수 라벨, 두 열, index 미저장; 실제 템플릿 대조 도구 제공 |
| 가중치 | 기본 `weights/model.pt`, 모델·전처리·클래스 매핑을 함께 저장 |
| GPU 공용 환경 | 서버 확인 스크립트는 설치하지 않음. `torch` 버전 미고정 |
| AI 사용 | 데이터 없이 코드 작성·가상 입력 CPU 검증. 실제 데이터 실행은 사용자가 서버에서 수행 |
| Git·배포 | 데이터·로그·예측은 제외. 최종 가중치만 명시적 별도 배포 필요 |

## 베이스라인과의 차이

원본 v7은 센서 5개, 이미지 밝기 통계, 과거 30초 통계, 로지스틱 회귀를 사용합니다. 팀 모델은 이미지 CNN과 센서 MLP를 결합하고, 후속 설정으로 직전값 대체와 비온도 센서의 과거 피처도 지원합니다. 원본 시계열 구현이 규정 위반이라고 판정한 것은 아닙니다. 과거 이력 허용과 임의 부분 입력 조건의 상세 관계는 운영진 확인 없이 확대 해석하지 않습니다.

원본의 입력 컬럼·라벨·split 기준 경로는 유지합니다. `--data_dir` 학습 진입점을 제공하고 `test.py --model`은 `--checkpoint`의 별칭으로 받습니다. 모델 형식이 달라 원본 `.joblib` 가중치를 불러올 수는 없습니다. 원본처럼 `--refit_train_val`을 지원하지 않으며, 자체 CV·최종 재학습은 추후 별도 구현과 검증이 필요합니다.

## 문서 차이의 처리

- 제출 가이드는 `torch` 버전을 적지 않도록 안내하고, GPU 가이드는 `torch>=2.7` 같은 하한을 예시로 듭니다. 양쪽 목적에 맞춰 `requirements.txt`에는 `torch`만 두고 환경 확인 코드가 최소 버전을 검사합니다. 실제 버전은 실행 기록에 저장합니다.
- DAKER는 100MB 초과 가중치에 링크를 요구합니다. 제출 가이드의 25MB는 웹 업로드 제한 맥락도 포함합니다. 25MB 초과 파일은 링크로 제공하면 두 안내의 배포 요구를 충족하기 수월합니다.
- Train+Validation 학습은 허용되지만 학습에 쓴 분할의 점수를 검증 성능으로 보고하면 안 됩니다. 현재는 Train 학습·Validation 검증만 제공합니다.

## 확인 범위의 한계

- 실제 CSV 파일명·이미지 존재 여부·압축 해제 결과·실제 패키지·GPU 동작은 검사하지 않았습니다. 서버 명령은 공식 배포 구조에 맞춘 것입니다.
- 실제 학습·Validation 점수·Test 예측·GPU 재현성·최종 선택 파일 재현은 사용자가 서버에서 확인해야 합니다.
- `check_submission.py`는 공식 검사항목을 참고해 만든 팀 도구입니다. 형식·일관성이 통과해도 모델의 정확도나 모든 규정 준수가 자동 인증되는 것은 아닙니다.
- 검증된 최종 가중치, 실제 실행 환경, 평가 결과, 최종 파일명과 배포 링크는 학습 후 README에 채워야 합니다.
